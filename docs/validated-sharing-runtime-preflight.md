# Pin the complete reader's optional runtime before another sharing pair

The [prospective issue #4 protocol](https://github.com/jimmy-sim/poker-ai/issues/4#issuecomment-6991520465)
was published on November 18 before this branch's source or new complete
comparison. [PR #92](validated-prerequisite-sharing-result.md) remains a
failed fixed pair: its first ordinary child used a base environment without
Numba package metadata and stopped before the validated-share child began.
The public failure is retained and is not rerun for a favorable outcome.

## Question and definition of done

Can the already qualified, root-local validated-sharing candidate preserve
the complete ordinary reader's result **and work** in the pinned optional
Python 3.11.17/NumPy 2.4.6 environment with Numba 0.68.1 and OpenSpiel
2.0.2? All seven original prerequisite loaders still run per archive root.
This is a behavior test, not a skipped-work or CPU-saving experiment.

1. Add a thin launcher that fails before creating pair output or starting a
   child unless the actual interpreter is the fixed optional Python 3.11.17
   environment, NumPy is 2.4.6, Numba is 0.68.1, OpenSpiel is 2.0.2,
   `PYTHONPATH` is absent, the branch is clean and pushed, and the lock and
   pinned inputs are unchanged. Compare the saved Python/NumPy/Numba runtime
   fields of both published real own artifacts with the installed metadata.
   Read and hash the complete installed OpenSpiel Apache-2.0 license before
   use. No reference output or training is constructed during this
   metadata preflight. A mismatch stops without a pair or fallback.
2. Keep the three PR #92 candidate scripts, all scientific source, config
   and input bytes, the fixed seeds `[20261301,20261302,20261303]`, all
   original loader/validator calls, work counters, predecessor identity and
   original 180-second own, 900-second per-child, 1,800-second pair and
   120-second failure-save caps unchanged. Reauthenticate the earlier public
   seven-loader own proof only while those candidate and pinned-input hashes
   match exactly. No duplicate own collection is needed under that exact
   carry-forward condition.
3. Before any complete run, qualify and publish the new launcher source:
   focused acceptance and fail-closed tests, both clean locked base roles,
   both complete optional roles, Ruff, formatting, strict mypy, all-files
   hooks and both hosted jobs. Verify the actual runtimes and whole tested
   checkout tree, retain the six-role record, and confirm its public bytes.
4. Launch **one** fresh ordinary-then-validated-share complete pair in the
   pinned optional runtime. The unchanged complete runner must observe two
   independent archive roots per child, seven original loader calls per
   root, six donor substitutions per shared root, three reads, 432 profiles,
   1,152 fixed conditions, three reference workers and exact complete
   result/work/predecessor identity. Preserve all partial failures. Do not
   retry or fall back after a failed gate.
5. Publish raw pair evidence before a data-only report. Reproduce any
   numerical exports on both locked runtimes with reader, numerical and
   reference entry points blocked. Complete final local and hosted checks
   before a history-preserving merge.

The old missing-Numba failure, 912.54/900 forecast failure, 2.390%/1%
known-game accuracy failure and rejected full-context-copy result remain
failed. Passing this question could establish complete sharing behavior
under one observed pair; it cannot establish CPU savings or a new strategy,
default, fresh/global admission or real-money use. Reference outputs stay
comparison-only and never enter training. Codex assisted with the protocol;
human hands-on time was not recorded.
