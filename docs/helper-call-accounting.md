# Account for validation helper calls

Prospective component contract, November 13, 2026; issue #4; Codex assisted.
The completed resource trace records CPU in reaped children as well as in the
main Python process. It does not identify each command's contribution. The
older elapsed profile measured a different copy and cannot fill that gap.
Before choosing another optimization, build a transparent command recorder.

This milestone is software foundation only. It does not wire or run a real
source-validation collector, launch a new poker audit, optimize a helper, admit
performance or change any strategy. No formal collection is planned in the
remaining November13 window. A later collector must bind its effective source,
complete/publish all six actual-runtime source roles, and fix its own command
cap/config before any actual source-path measurements. Existing scientific
seeds, work counts,7200/900study caps and failed gates remain unchanged.

The recorder observes `subprocess.run`, including calls through `check_output`.
Recognize only builtin argv lists/tuples for Git with `-C` equal to the checked
repository and declared read-only subcommands. Record category and argument hash,
not raw arguments, environment, input or output contents. Supported output is
represented by type,size and SHA256; text hashing is explicitly UTF8 with
surrogatepass, not a claim about original wire bytes. Unknown shapes/commands
execute unchanged but count as unsupported coverage, without argument/output
recording. A future complete source trace must reject unsupported coverage.

Capture nearby own-process/reaped-child resource snapshots over each synchronous
call. Their increment belongs to that observation interval, not necessarily that
PID: unrelated concurrent children would confound attribution. This observer is
for an eventual source-only sequential path, not parallel native-worker use.
It must never label a counter delta as exclusive per-process CPU. OS-zero,
non-atomic snapshot, cumulative-peak and unit caveats from the previous observer
remain. No machine-wide/private process data is collected.

Tests must cover original return-object/bytes identity, keyword argv and
check_output, supported/unsupported coverage and privacy, original exception
identity, partial starts, logging failures, source-observer restoration and
accounting/raw-delta integrity. Use tiny temporary Git/software fixtures only;
no real-poker or source-path timing conclusions. Full project checks and both
hosted jobs precede merge. Publish accurate component status and the learning
journal; do not call this a complete collector or measured speedup.
